# فهرست درخواست‌های قابلیت

هر قابلیت با شناسهٔ جداگانه ثبت می‌شود. موارد را بر اساس دسته، خواسته، وضعیت سورس، شواهد اجرا و اقدام بعد مرتب می‌کنیم.

## دسته‌ها

- تب‌ها و پنجره
- نمایش و راست‌به‌چپ
- ورودی و کلیپ‌بورد
- پوسته و گردش‌کار Agent
- تنظیمات و یکپارچه‌سازی
- سایر

## F-001 — تغییر نام هر تب

- **دسته:** تب‌ها و پنجره
- **خواسته:** با راست‌کلیک روی هر تب، نام همان تب قابل تغییر باشد.
- **وضعیت سورس:** پیاده‌سازی شده در سورس محلی؛ منوی `Rename tab...` و تابع تغییر نام در `MainWindow.xaml.cs` وجود دارد و README هم آن را فهرست کرده است.
- **وضعیت نسخه‌ها:** فرایند نصب کاربری 1.1.4 و نصب سیستمی 1.1.2 جداگانه در حال اجرا هستند.
- **تأیید رابط کاربری:** در این نوبت منوی Rename داخل پنجره آزمایش نشد؛ وجود کد به‌تنهایی تأیید اجرای رابط نیست.
- **اقدام بعد:** اگر لازم است، رابط نسخهٔ 1.1.4 را بازبینی و رفتار تغییر نام را دستی تأیید کن.

## ثبت درخواست‌های بعدی

برای هر درخواست تازه، شناسهٔ بعدی را اختصاص بده، دسته‌اش را مشخص کن و وضعیت پیاده‌سازی و تأیید اجرایی را جدا ثبت کن.

## F-002 — پروژه‌های ذخیره‌شده، سشن‌ها و انتخاب Agent

- **دسته:** پروژه‌ها و نشست‌ها
- **ساخت/بازکردن پروژه:** با زدن `+` و انتخاب CMD، PowerShell یا WSL، فهرست پروژه‌های ذخیره‌شده نمایش داده شود و امکان ساخت پروژهٔ تازه هم باشد. پروژهٔ تازه یک نام و یک یا چند مسیر پوشه از File Explorer می‌گیرد. انتخاب پروژهٔ موجود همان پروژه را باز کند و نام و مسیرهایش دوباره پرسیده نشود.
- **ذخیره‌سازی:** مشخصات پروژه، نام و فهرست مسیرها، سشن‌های وابسته، نام هر سشن و اطلاعات لازم برای بازگشت به آن‌ها در دیتابیس/حافظهٔ پایدار خود برنامه ذخیره شود تا پس از بستن و اجرای دوباره هم باقی بماند.
- **تب و مدیریت پروژه:** تب بالایی فقط نام پروژه را نشان دهد. با راست‌کلیک روی آن بتوان پروژه را rename کرد، مسیرها را دید/ویرایش/اضافه/حذف کرد، سشن‌ها را باز کرد و Agent پروژه یا سشن را انتخاب/عوض کرد.
- **سشن‌ها:** هر پروژه چند سشن مستقل، مانند چت‌های جداگانهٔ Codex، داشته باشد. سشن تازه زیر همان پروژه ایجاد شود، به مسیرها و زمینهٔ پروژه وصل باشد و نامش قابل تغییر باشد. فهرست سشن‌ها باید سشن‌های ذخیره‌شده را نشان دهد و بازکردن/سوییچ به هر سشن همان سشن را در همان تب پروژه بازیابی کند؛ تب بالایی جدید ساخته نشود و محتوای سشن‌ها با هم قاطی نشود.
- **انتخاب Agent:** از منوی پروژه/سشن بتوان Agent را انتخاب یا عوض کرد؛ نمونه‌های نام‌برده‌شده: Cloud Agent، Codex و OpenCode. هویت Agent انتخاب‌شده برای پروژه/سشن ذخیره شود. امکان انتقال تاریخچهٔ یک Agent به Agent دیگر هنوز تعریف نشده و نباید پیش‌فرض گرفته شود.
- **اعلان پایان کار:** وقتی Agent در یک سشن کارش را تمام کرد، روی تب پروژه یا کنار همان سشن نشانگر/اعلان بیاید تا کاربر بتواند به آن سشن سوییچ کند و نتیجه را ببیند.
- **وضعیت:** درخواست تأیید و ثبت شد؛ هنوز پیاده‌سازی نشده است. امکانات فعلی انتخاب پوشه/نام‌گذاری تب به‌تنهایی مدیریت پایدار پروژه، دیتابیس سشن‌ها، سوییچ Agent و اعلان پایان کار را پوشش نمی‌دهد.
- **موارد نیازمند تصمیم در طراحی:** اگر چند مسیر وجود دارد، مسیر کاری اولیهٔ هر سشن چگونه انتخاب شود؛ «بازگشت به سشن» برای هر Agent دقیقاً از چه سازوکار پشتیبانی‌شده‌ای استفاده کند؛ و اعلان پایان کار کجا و با چه رفتاری دیده شود.
