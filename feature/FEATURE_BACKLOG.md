## F-002 — پروژه‌های ذخیره‌شده، سشن‌ها و انتخاب Agent

- **دسته:** پروژه‌ها و نشست‌ها
- **ساخت/بازکردن پروژه و مسیر منوها:** جریان از `+` و انتخاب نوع ترمینال CMD، PowerShell یا WSL شروع شود. گزینهٔ Agent فقط `X Agents CLI` باشد؛ منوی خود X Agents CLI فهرست و مدیریت Codex، Claude Code، OpenCode و Agentهای دیگر را انجام دهد. بعد منوی پروژه‌ها، سشن‌ها و ساخت موارد تازه نمایش داده شود. با انتخاب پروژه، ابتدا فهرست سشن‌های همان پروژه نمایش داده شود؛ سشن تازه خودکار ساخته نشود. پروژهٔ تازه نام پروژه و یک یا چند مسیر پوشه از File Explorer می‌گیرد؛ این تنظیمات ذخیره شوند.
- **ذخیره‌سازی و حفظ همه‌چیز:** پروژه‌ها، نام‌ها، مسیرهای پروژه و هر سشن، هویت سشن پروژه و اطلاعات لازم برای بازیابی در دیتابیس پایدار برنامه ذخیره شوند و با بستن برنامه یا سوییچ از بین نروند. عوض‌کردن Provider نباید سشن پروژه یا مسیر کاری‌اش را عوض کند؛ Provider جدید به همان `projectSessionId` و همان مسیرها وصل می‌شود. گفت‌وگوی native هر Provider جداگانه حفظ شود تا با برگشت به آن Provider، گفت‌وگوی خودش ادامه پیدا کند. انتقال عین transcript native از یک Provider به Provider دیگر جزو شرط نیست.
- **تب و مدیریت پروژه:** تب بالایی نام پروژه و سشن فعال را باهم نشان دهد، مثلاً `ProjectName — SessionName`. با راست‌کلیک روی همان تب بتوان پروژه را rename کرد، مسیرها را دید/ویرایش/اضافه/حذف کرد، سشن‌ها را باز کرد و Agent پروژه یا سشن را انتخاب/عوض کرد.
- **سشن‌ها:** هر پروژه چند سشن مستقل، مانند چت‌های جداگانهٔ Codex، داشته باشد. هر سشن زیر همان پروژه ذخیره شود و نام و مسیرهای پوشهٔ مخصوص خودش قابل ویرایش باشد. پس از انتخاب پروژه، کاربر سشن موجود را انتخاب کند یا در فهرست `Sessions` با زدن `+` سشن تازه بسازد؛ هنگام ساخت، ابتدا نام سشن پرسیده شود و سپس امکان افزودن مسیر پوشه به همان سشن ارائه شود. انتخاب سشن همان را در تب پروژه فعال کند. با راست‌کلیک روی تب پروژه و سشن فعال، گزینهٔ `Sessions` با فلش فهرست سشن‌ها و نامشان را نشان دهد؛ کاربر بتواند از همان فهرست سشن را rename، مسیرهایش را ویرایش، یا فعال کند. سوییچ از این فهرست باید در همان تب پروژه انجام شود و تب تازه نسازد؛ محتوای هیچ سشنی گم یا با سشن دیگر مخلوط نشود.
- **انتخاب موتور و Provider:** در منوی بعد از انتخاب Shell، موتور قابل‌انتخاب `X Agents CLI` است. پس از بازکردن پروژه و انتخاب یک سشن، همان موتور در runtime مختص همان سشن اجرا/بازیابی شود؛ گزینهٔ Agent در منوی هر سشن نیز همان runtime را در همان تب پروژه فعال کند. انتخاب و مدیریت Providerهایی مثل Codex، Claude Code و OpenCode از داخل خود X Agents CLI انجام می‌شود، نه با ساختن تب یا سشن تازه در ترمینال. با سوییچ Provider، هویت همان project session و مسیرهایش ثابت می‌مانند؛ هر Provider در همان پروژه گفت‌وگوی native مستقل خودش را نگه می‌دارد و هنگام بازگشت همان را resume می‌کند. واردکردن خودکار متن مکالمهٔ Provider قبلی به Provider جدید لازم نیست.
- **اعلان پایان کار:** وقتی Agent در یک سشن کارش را تمام کرد، اعلان شماره‌دار/نشانگر کنار تب پروژه یا همان سشن بیاید تا معلوم باشد کدام سشن یا چند سشن کارشان تمام شده است. با انتخاب اعلان، کاربر بتواند به همان سشن سوییچ کند و نتیجه را ببیند. هم‌زمان یک صدای کوتاه (مثل جیلینگ) پخش شود.
- **وضعیت فعلی سورس محلی (2026-10-18):** جریان shell → `X Agents CLI` → پروژه → سشن و مدیریت پروژه/سشن از تب در سورس است. runtime موتور X Agents CLI برای هر سشن جداگانه در محل دادهٔ برنامه مستقر می‌شود؛ فایل‌های منبع کپی‌شده حذف یا جابه‌جا نشده‌اند. نام‌ها، مسیرهای پروژه/سشن، پروفایل، transcript، سشن فعال و شمارندهٔ پایان کار در SQLite نگهداری می‌شوند. هر سشن پروژه به ConPTY broker جداگانه با شناسهٔ پایدار خودش وصل می‌شود؛ بستن UI فقط detach می‌کند و اجرای دوبارهٔ برنامه به shell زنده وصل می‌شود. این ماندگاری تا logoff، shutdown، پایان shell، یا از دست‌رفتن خروجی بیش از پنجرهٔ replay (۵۱۲ KiB) محدود است. X Agents CLI در runtime مختص سشن و با شناسهٔ پروژه/سشن و فایل handoff اجرا می‌شود. Providerهای دارای adapter با native session خودشان ادامه می‌یابند؛ موارد دیگر transcript handoff دارند و تاریخچهٔ یک Provider به Provider دیگر منتقل نمی‌شود. منوی `Sessions` امکان انتخاب، rename، ویرایش مسیر و افزودن سشن را دارد؛ `Completed` به سشن اعلان‌دار برمی‌گردد. مسیر کاری زنده با تغییر مسیر تا اجرای مجدد process تغییر نمی‌کند.
- **شواهد آزمون (2026-10-18):** بیلد Release PASS با ۰ هشدار/خطا؛ Buffer ۱۶/۱۶ PASS؛ Render suite PASS؛ smoke پنجره PASS؛ تست broker detach/reconnect PASS؛ Node AgentEngine ۷/۷ PASS، از جمله سوییچ Codex↔Claude روی یک `projectSessionId` و `cwd` با resume گفت‌وگوی native جداگانهٔ هرکدام؛ syntax check چهار فایل PASS. ریزنتیجه در `feature/TESTS_TO_RUN.md` است. آزمون رابط کامل و Provider زنده جداگانه دستی‌اند.
- **محدودیت‌های باقی‌مانده:** گفت‌وگوی native بین Providerهای متفاوت وارد هم نمی‌شود؛ هر Provider گفت‌وگوی native خودش را resume می‌کند. Broker پردازش عادی مخفی است و پس از logoff/shutdown خاتمه می‌یابد. سوییچ از رابط و اجرای Provider زنده هنوز تأیید دستی می‌خواهد. نسخه‌های نصب‌شده تغییر نکرده‌اند.
- **موارد نیازمند تصمیم/محدودیت معماری:** برای چند مسیر، اولین مسیر ذخیره‌شده مسیر کاری اولیه است و بقیه مسیرهای قابل‌پشتیبانی از adapter به CLI داده می‌شوند. تغییر مسیر یک سشن درحال اجرا، shell زنده را جابه‌جا نمی‌کند و پس از اجرای مجدد آن runtime اعمال می‌شود.
- **جزئیات رابط:** منوها به‌صورت آبشاریِ مجاور با فلش‌های بومی WPF باز شوند؛ زنجیرهٔ `+ → Shell → X Agents CLI → Project → Session` و منوی راست‌کلیک تب باید یک سبک هماهنگ با ترمینال داشته باشد. زیرمنوی پروژه امکان rename، پوشه‌ها و حذف پروژه را می‌دهد؛ زیرمنوی سشن امکان switch، افزودن سشن، rename، افزودن/ویرایش پوشه‌ها و حذف سشن را می‌دهد.
- **حذف امن:** حذف پروژه/سشن پس از تأیید، رکوردها، تاریخچه و runtime اختصاصی همان سشن را حذف می‌کند؛ پوشه‌های واقعی پروژه و فایل‌های داخلشان پاک نمی‌شوند. حذف سشن فعال باید سشن باقی‌مانده را فعال کند.
- **وضعیت سورس (2026-10-18):** منوهای Shell/Agent/Project/Session آبشاری‌اند؛ عملیات مدیریت و حذف پروژه/سشن به منوها افزوده شد؛ حذف پروژه/سشن broker همان سشن را متوقف می‌کند؛ فرم‌های نام و پوشه از پنجرهٔ تیرهٔ هم‌تم با نوار عنوان برنامه استفاده می‌کنند.
- **شواهد آزمون (2026-10-18):** `dotnet build tests/RtlTerminal.RenderTests/RtlTerminal.RenderTests.csproj -c UITest --no-restore --nologo` با صفر هشدار/خطا پاس شد. کل RenderTests پاس شد؛ آزمون ساختاری تازه زنجیرهٔ منو و عملیات مدیریت را می‌سنجد و آزمون SQLite حذف متادیتا و باقی‌ماندن پوشهٔ واقعی را می‌سنجد. بررسی hover با ماوس و پذیرش بصری در پنجرهٔ تعاملی هنوز دستی انجام نشده است.

## F-003 — حساب‌های Coding Agents

- **دسته:** پوسته و گردش‌کار Agent
- **منو:** داخل X Agents CLI گزینهٔ Coding Agents قرار دارد؛ ترتیب Codex، Claude Code (Cloud)، Antigravity است. ورودی قدیمی «Antigravity Sessions» از منوهای اصلی برداشته شود و نشست‌های ذخیره‌شده‌اش حذف نشوند.
- **Codex:** پنج پوشهٔ ازقبل‌واردشدهٔ `.codex-account1` تا `.codex-account5` با نام Account 1 تا Account 5 نشان داده شوند. انتخاب هرکدام همان `CODEX_HOME` را با `codex -c 'cli_auth_credentials_store="file"'` اجرا کند؛ هیچ فرمان `codex login` و هیچ صفحهٔ ورود دوباره اضافه نشود. همهٔ پنج حساب هم‌رتبه‌اند و هیچ‌کدام primary/secondary علامت‌گذاری نمی‌شود. پیکربندی استاندارد `.codex` دست‌نخورده می‌ماند و جزو Account 1 تا 5 محسوب نمی‌شود. ایمیل، نوع طرح و محدودیت مصرف از `account/read` و `account/rateLimits/read` همان Codex App Server خوانده و در ورود به منو تازه می‌شوند؛ این خواندن درخواست مدل نمی‌فرستد.
- **Claude Code:** حساب پیکربندی فعلی حفظ شود؛ `+ Add account` می‌تواند پوشهٔ مستقل `CLAUDE_CONFIG_DIR` بسازد و ورود رسمی Claude را برای همان پوشه اجرا کند. تا وقتی CLI وضعیت ایمیل/مصرف را در منبع رسمیِ قابل‌خواندن ندهد، UI باید آن را نامشخص اعلام کند.
- **Antigravity:** گزینهٔ Coding Agents از `agy` خودش و ورود ذخیره‌شدهٔ Windows استفاده کند؛ ورود نخست با اجرای خود `agy` انجام شود و اجرای بعدی همان حساب ذخیره‌شده را باز کند. Gemini CLI و `GEMINI_CLI_HOME` برای ورود Antigravity به‌کار نروند. CLI ورود را از keyring ویندوز می‌خواند؛ راهنمای رسمی می‌گوید ایمیل در header تعاملی agy دیده می‌شود و `/usage` محدودیت/مصرف را می‌دهد. خروجی ماشین‌خوان `/usage` که این منو می‌خواند ایمیل را نمی‌دهد، پس ایمیلِ ردیف حساب هنوز خودکار پر نمی‌شود. مستندات رسمی: https://www.antigravity.google/docs/cli/install/ و https://www.antigravity.google/docs/getting-started?tab=cli.
- **وضعیت سورس:** منو و مسیر اجرای حساب‌ها در سورس پیاده‌سازی شد؛ پنج خانهٔ Codex با metadata شناسایی می‌شوند و هیچ فایل ورود دست‌کاری یا ثبت نمی‌شود. بیلد Release ایزوله و آزمون‌های خودکار PASS؛ آزمون تعاملی برنامه هنوز باقی است. نسخهٔ نصب‌شده تغییر نکرده.
- **بررسی زندهٔ read-only (2026-10-18):** هر پنج Codex home از App Server ایمیل و rate limits برگرداندند؛ ایمیل/مصرف در فایل‌ها ثبت نشد. `agy /usage` نیز موفق شد و Windows Credential Manager ورودی Antigravity داشت؛ این نشان می‌دهد اکنون دسترسی/نشست قابل استفاده است، پس login تازه را اجرا نکردیم. آزمون تعامل و پذیرش UI هنوز جداست.
- **محدودیت:** Codex App Server API برای هویت و rate limits آزمایشی است؛ نسخه‌های ناسازگار باید وضعیت را «ناموجود» نشان دهند، نه حدس بزنند. Claude/Antigravity ایمیل و Usage مطابق دسترسی رسمی CLI نشان می‌دهند؛ این داده‌ها در صورت نبود API حدس زده نمی‌شوند.
- **مرجع آزمون و وضعیت هر مورد:** `feature/TESTS_TO_RUN.md`, بخش F-003.
