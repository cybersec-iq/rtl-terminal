# فهرست درخواست‌های قابلیت

هر قابلیت با شناسهٔ جداگانه ثبت می‌شود. موارد را بر اساس دسته، خواسته، وضعیت سورس، شواهد اجرا و اقدام بعد مرتب می‌کنیم.

## دسته‌ها

- تب‌ها و پنجره
- نمایش و راست‌به‌چپ
- ورودی و کلیپ‌بورد
- پوسته و گردش‌کار Agent
- تنظیمات و یکپارچه‌سازی
- سایر

## F-001 — تغییر نام هر تب

- **دسته:** تب‌ها و پنجره
- **خواسته:** با راست‌کلیک روی هر تب، نام همان تب قابل تغییر باشد.
- **وضعیت سورس:** پیاده‌سازی شده در سورس محلی؛ منوی `Rename tab...` و تابع تغییر نام در `MainWindow.xaml.cs` وجود دارد و README هم آن را فهرست کرده است.
- **وضعیت نسخه‌ها:** فرایند نصب کاربری 1.1.4 و نصب سیستمی 1.1.2 جداگانه در حال اجرا هستند.
- **تأیید رابط کاربری:** در این نوبت منوی Rename داخل پنجره آزمایش نشد؛ وجود کد به‌تنهایی تأیید اجرای رابط نیست.
- **اقدام بعد:** اگر لازم است، رابط نسخهٔ 1.1.4 را بازبینی و رفتار تغییر نام را دستی تأیید کن.

## ثبت درخواست‌های بعدی

برای هر درخواست تازه، شناسهٔ بعدی را اختصاص بده، دسته‌اش را مشخص کن و وضعیت پیاده‌سازی و تأیید اجرایی را جدا ثبت کن.

## F-002 — پروژه‌های ذخیره‌شده و سشن‌های قابل‌تعویض

- **دسته:** پروژه‌ها و نشست‌ها
- **خواسته:** ساخت پروژه با نام و چند مسیر پوشه، فقط یک بار انجام شود و تنظیمات ذخیره بماند. بعداً با انتخاب CMD، PowerShell یا WSL، پروژهٔ ذخیره‌شده انتخاب و در همان پروژه باز شود؛ مسیرها هر بار دوباره پرسیده نشوند.
- **مدیریت پروژه:** تب بالایی نام پروژه را نشان دهد. از منوی راست‌کلیک بتوان نام پروژه را عوض کرد، مسیرهای پوشه را اضافه یا حذف کرد و سشن‌های پروژه را مدیریت کرد.
- **سشن‌ها:** هر پروژه چند سشن مستقل، شبیه چت‌های جداگانهٔ Codex، داشته باشد. سشن تازه زیر همان پروژه ایجاد شود و همان زمینه و مسیرهای پروژه را بگیرد. جابه‌جایی میان سشن‌ها در همان تب پروژه انجام شود و تب بالایی تازه نسازد؛ محتوای هر سشن هنگام تعویض حفظ شود.
- **اعلان پایان کار:** وقتی Agent در یک سشن کارش را تمام کرد، روی تب پروژه یا کنار فهرست سشن‌ها نشانگر/اعلان بیاید تا کاربر بتواند به همان سشن برگردد و نتیجه را ببیند.
- **وضعیت:** درخواست تأیید و ثبت شد؛ هنوز پیاده‌سازی نشده است. امکانات فعلی انتخاب پوشه/نام‌گذاری تب به‌تنهایی این مدیریت پایدار پروژه و سشن‌های چندگانه را پوشش نمی‌دهد.
- **نکتهٔ اجرایی برای طراحی:** یک پروژه می‌تواند چند مسیر داشته باشد؛ هر سشن باید پیوند پایدارش به پروژه و مسیرها را حفظ کند. جزئیات انتخاب مسیر کاری پیش‌فرض و سازوکار نگهداری گفت‌وگوی Agent هنگام سوییچ در مرحلهٔ طراحی مشخص شود.
