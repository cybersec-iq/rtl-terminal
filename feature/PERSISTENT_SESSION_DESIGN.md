# نشست پایدار ConPTY

## اتصال پیاده‌سازی‌شده

- هر سشن پروژه شناسهٔ پایدار خودش را دارد؛ همان شناسه به‌عنوان شناسهٔ broker استفاده می‌شود.
- `MainWindow` هنگام بازکردن سشن به broker موجود وصل می‌شود و فقط وقتی broker در دسترس نیست، shell تازه می‌سازد. تب‌های عادی همچنان از ConPTY محلی استفاده می‌کنند.
- broker یک نمونهٔ مخفی از exe جاری است و مالک ConPTY و shell باقی می‌ماند. بستن یا dispose کردن پنجرهٔ رابط فقط اتصال named pipe را جدا می‌کند.
- خروجی زمان قطع رابط تا ۵۱۲ KiB در صف replay نگهداری می‌شود. named pipe فقط برای کاربر جاری مجاز است.
- transcript قابل‌نمایش سشن در SQLite checkpoint می‌شود. هنگام اتصال مجدد، خروجی زندهٔ broker استفاده می‌شود؛ transcript ذخیره‌شده جایگزین صفحهٔ پایدار ترمینال نیست.
- هر سشن X Agents CLI فایل handoff متنی خودش را در runtime برنامه دارد. X Agents CLI متغیرهای `XAGENT_PROJECT_SESSION_ID` و `XAGENT_TRANSCRIPT_HANDOFF_FILE` را دریافت می‌کند.

## چرخهٔ عمر و محدودیت‌ها

- broker فرایند مخفی معمولی است، نه سرویس ویندوز. پس از بسته‌شدن UI زنده می‌ماند و با اجرای دوبارهٔ برنامه از شناسهٔ ذخیره‌شده دوباره متصل می‌شود؛ خروج از حساب ویندوز، خاموشی، یا پایان shell آن را خاتمه می‌دهد.
- اگر UI به اجبار بسته شود، broker تا پایان shell زنده می‌ماند و می‌تواند دوباره متصل شود. خروجی بازپخش محدود است؛ بعد از بیش از ۵۱۲ KiB خروجیِ زمان قطع، قدیمی‌ترین بایت‌ها حذف می‌شوند.
- شناسهٔ provider و native resume برای adapterهایی که در registry تعریف شده‌اند جداگانه حفظ می‌شود. این کار تاریخچهٔ یک provider را به provider دیگری تبدیل نمی‌کند. برای CLIهای بدون adapter، transcript handoff متن‌محور است و ادامهٔ native تضمین نمی‌شود.
- اجرای فرایند Agent پس از بستن UI تا وقتی broker و shell زنده‌اند ادامه دارد؛ پس از logoff یا restart ویندوز، ادامهٔ فرایند ممکن نیست.
- آزمون اتصال مجدد broker در `tests/RtlTerminal.RenderTests/PersistentSessionBrokerTests.cs` است؛ در 2026-10-18 با detach، replay marker، اتصال دوباره و توقف تمیز PASS شد.

نصب‌های موجود با این تغییرات دست‌کاری نشده‌اند.
